# 代码出处与负优化审查报告

审查日期：2026-11-12
审查范围：网站前端、APP 核心（播放器、网络 API、配置、缓存、诊断、UI）、CI 配置、架构文档
审查目标：确认代码出处是否借鉴开源项目/模板；识别负优化、过度设计、潜在漏洞与安全风险

## 一、出处审查结论

全部代码均为自研实现，未发现对开源项目、开源模板的借鉴。

自研清单（按模块）：

- 网站前端：`index.html`、`styles.css`、`app.js`、`classic/index.html` 均为手写页面与样式，使用自定 CSS 变量，未引入 Bootstrap、Tailwind 等外部框架。
- 架构文档：`ARCHITECTURE.md` 为自写架构说明。
- APP 核心：播放器（`PlayerActivity`）、播放内核（`MusicKernel`）、网络接口（`LiveApi`、`SourceApi`、`UpdateChecker`）、配置解析（`TvBoxConfig`）、磁盘缓存（`DiskCache`）、内容过滤（`ContentFilter`）、播放失败诊断（`NetDiag`）、性能体检（`PerfDiag`）、守护体检（`GuardianActivity`）等均自写实现，无第三方开源框架依赖。
- 必要依赖：仅使用 Android 官方组件（ExoPlayer 播放器库、Android 原生 `android.*`），属正当功能依赖，非开源借鉴。

结论：出处清白，无开源模板借用，无外部框架套用。

## 二、负优化与过度设计审查结论

代码设计取舍均有明确理由注释，未发现明显的负优化、过度设计或冗余依赖：

- 播放器选择 ExoPlayer 而非系统 VideoView，理由为系统 VideoView 对 HLS 变体、FLV/MKV/HEVC 支持残缺，直播基本不可用（`PlayerActivity.java:32-41`）。
- 播放器控制条自绘，理由为 PlayerView 自带控制条过于简单且会压画面中间；自绘为底部渐隐玻璃 + 64dp 大按钮，遥控器焦点明显（`PlayerActivity.java:35-37`）。
- 壁纸采用自家 Bitmap 管理而非 WallpaperManager，理由为不申请权限、不碰系统设置、卸载即净，并对 4K 原图做解码前尺寸确认与降采样防 OOM（`WPManager.java:19-25`）。
- 更新检查采用多加速源 + 严谨版本比较，避免误判旧包（`UpdateChecker.java:11-23,60-64`）。
- 内容过滤只收明确关键字，避免误杀正经剧名（`ContentFilter.java:6-11`）。
- 播放失败诊断（`NetDiag`）与性能体检（`PerfDiag`）为诊断工具，逻辑清晰、兼容边界处理得当。

结论：无异常负优化，无过度设计。

## 三、漏洞与风险清单

按风险等级列出，供其他 AI 进一步评估与处理：

### 1. 签名校验值硬编码（低风险，建议改进）

位置：`SelfCheck.java:20-21`

当前将官方包完整 SHA-256 签名指纹写死在代码中，用于校验是否官方包。

风险：校验值一旦泄露，理论上可伪造官方包；单点为硬编码，无服务端下发。当前属官方包完整性校验的常规做法，风险较低，但属于可改进点。

边界说明：代码只取 `signatures[0]`，若设备预置多签名可能误判，属边缘情况，可接受。代码注释已说明换签名钥匙必须同步修改 `OFFICIAL`。

建议：将校验值改为由服务端下发或改用密钥签名机制，降低单点硬编码风险。

### 2. 更新检查的 JSON 解析偏脆弱（低风险，建议改进）

位置：`UpdateChecker.java:205-290`

`parse`、`bestRelease`、`extract` 采用字符串位置扫描解析 `version.json` 与 GitHub releases 列表。

风险：解析逻辑对格式变化敏感，解析健壮性一般；当前解析的均为自维护 JSON，实际风险较低。

建议：改用标准 JSON 解析库，提升对格式变化的容错能力。

### 3. 直播源缓存静态共享累积（低风险，建议改进）

位置：`LiveApi.java:31`

`LiveApi.CACHE` 为静态共享列表，解析时持续累积，未做定期清理。

风险：直播源数量规模较小时影响有限；若未来源规模增长，静态列表累积可能增加内存占用。

建议：控制缓存规模或定期清理，降低长期内存占用。

### 4. 反射调用系统方法（低风险，兼容处理合理）

位置：`GuardianActivity.java:152-162`、`PerfDiag.java:329-351`

通过反射调用 `isIgnoringBatteryOptimizations` 等系统方法，用于兼容低版本 Android。

风险：反射调用系统方法在部分系统版本可能不稳定，但代码已做 try/catch，查不到时返回"未知"而非误报，兼容边界处理合理，非漏洞。

### 5. 安全合规检查（通过）

- 无 SQL 注入、无硬编码密钥、无 XSS 面：网站 JS 自写无内联脚本注入风险，播放页外部错误信息仅以文本展示，内容本地过滤。
- 无网络隧道、代理、流量转发，无第三方 Agent 安装，无灰产行为。
- 无违规系统管理命令：守护页仅跳转系统设置页，不执行系统管理操作。
- 依赖合规：minSdk 16，ExoPlayer 2.18.1 兼容老设备。

结论：安全合规，未发现严重安全漏洞。

## 四、改进建议汇总

1. `SelfCheck.java` 签名校验值改为服务端下发或密钥签名机制，降低硬编码单点风险。
2. `UpdateChecker.java` 的 JSON 解析改用标准 JSON 解析库，提升健壮性。
3. `LiveApi.java` 控制 `CACHE` 静态共享累积，定期清理或复用实例。
4. 反射调用系统方法处保持现有 try/catch 兼容处理，无需改动。

以上改进为可选优化，当前代码整体功能正确、出处清白、安全合规。
